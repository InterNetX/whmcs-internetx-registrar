# Contributing

## Before you start

- Open an issue first for significant changes so we can discuss the approach.
- For bug fixes and small improvements, a PR is fine without prior discussion.

## Development setup

```bash
cd src/install/modules/registrars/InterNetXJson
composer install
```

Run the tests before submitting:

```bash
./test.sh
```

The functional tests require network access to InterNetX's sandbox API and may be flaky — unit test failures are the ones to fix.

## Pull requests

- Make changes in `src/` only — `dist/` is generated by CI and should not be edited.
- Keep PRs focused on a single concern.
- Add or update unit tests for any logic changes in `app/Helpers/`.
- Ensure `./test.sh` passes locally before opening a PR.

## Reporting bugs

Use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md) and include your plugin version and WHMCS version.
